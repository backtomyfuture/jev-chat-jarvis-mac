# 微信即时通讯多维研判体系：沟通心理学、会话分析与对话行为研究

## 执行结论

面向微信单聊，最稳健的方案不是让模型直接猜“对方真实想法”，而是建立一个**分层、可证据回溯、允许不确定性**的研判体系：先识别显性事实与对话行为，再推断自我状态、关系信号和隐含诉求，最后判断位阶、时限、边界风险与冲突，并输出应对策略。Schulz von Thun 的“四面消息”、Berne 的 TA、Searle/ISO 的对话行为和 Conversation Analysis（CA）的序列结构分别解决“消息包含什么”“以何种心理姿态互动”“这句话在做什么”“它在上下文中如何回应前文”四个不同问题，不能相互替代。[^1][^2][^3][^4]

建议生产系统采用六个核心研判维度：**互动位阶、核心需求、回应期待、时间压力、边界风险、冲突状态**。每个维度只输出一个主标签，同时保留候选标签、置信度、证据片段与判断来源；情绪、话题、实体、显性 Speech Act 等作为独立辅助层，而不是混进一个总标签。

尤其需要坚持四条边界：

- 判断“本轮呈现的沟通姿态”，不诊断人格、动机或心理疾病。
- 区分“组织身份位阶”与“此刻话语中的互动控制权”。
- 区分“文字表达出的情绪”与“对方实际内心情绪”。
- 没有足够证据时输出“无法判断”，而不是把高语境沟通变成读心术。

## 理论整合框架

### 四耳模型的文本化

Schulz von Thun 的沟通方阵认为，一条消息同时包含事实信息、自我揭示、关系提示和诉求呼吁；发送者以“四个嘴”发出，接收者也可能偏用某一只“耳朵”理解。该模型由 Schulz von Thun 于 1981 年提出，原模型还强调上下文、措辞、语调和非语言线索会“限定”消息如何被理解。[^5][^1]

在微信文本中，可将四面落地为四个并行对象，而不是四选一分类：

| 消息面 | 系统要回答的问题 | 可抽取字段 | 文本判断依据 | 常见误判 |
|---|---|---|---|---|
| 事实面 | 对方明确说了什么？ | 事件、人物、对象、时间、数量、状态、因果、确定性 | 陈述句、数字、时间词、实体、否定、条件句、引用 | 把推断当事实；忽略“可能、听说、应该”等不确定性 |
| 自我面 | 对方暴露了怎样的当下状态？ | 显性情绪、关注点、约束、价值偏好、能力、意愿、承诺度 | 情绪词、模态词、自我指称、解释、犹豫、强调、承诺 | 把“本轮状态”升级成人格判断 |
| 关系面 | 对方如何定位双方关系？ | 尊重度、亲疏度、信任度、控制权、归责方向、面子威胁 | 称呼、礼貌缓和、命令、评价、讽刺、代词、责任归属 | 将简短等同冷漠；忽略个人聊天基线 |
| 诉求面 | 对方想让接收者接下来做什么？ | 目标动作、执行者、对象、截止时间、力度、显隐性、成功条件 | 祈使、问句、建议、暗示、条件、重复追问、未闭合邻接对 | 只看句式，不看间接请求与上下文 |

推荐的输出结构不是一句“对方不高兴”，而是：

```json
{
  "fact": {"summary": "两组数据尚未核完", "certainty": "明确"},
  "self_revelation": {"state": "进度受阻", "emotion": "轻度焦虑"},
  "relationship": {"stance": "向上汇报并寻求体谅"},
  "appeal": {"action": "协商延期", "explicitness": "隐含"},
  "evidence": ["还有两组数据没核完", "今晚可能有点悬"],
  "confidence": 0.82
}
```

**微信场景示例**：领导问“方案今天能给吗？”员工答“还有两组数据没核完，今晚可能有点悬。”事实面是“核验未完成”；自我面是“受约束、对按时完成缺乏把握”；关系面是“向有验收权者解释并降低归责”；诉求面并未直说“延期”，但在该问答序列中很可能是请求放宽截止时间。CA 的邻接对理论指出，问题会使回答成为下一轮的规范性相关行动，而不直接给出“能/不能”的回复本身也构成可解释的偏离。[^4][^6]

**产品规则**：四个面都允许为空或低置信度；事实面优先抽取，其他三面必须绑定证据。关系面与诉求面尤其需要最近多轮、双方角色、称呼变化和个人基线，不能只看末句。

### TA 与心理位阶

Berne 的 Transactional Analysis 把 ego state 定义为与相应行为模式相联系的一致的感受和经验模式，核心包括 Parent、Adult、Child；这些是可观察的互动状态，不等同于年龄，也不应被当成人格标签。[^2][^7][^8]

为了适配职场微信，建议使用五类功能性姿态：

| TA 姿态 | 核心特征 | 微信文本线索 | 典型例句 | 系统含义 |
|---|---|---|---|---|
| 控制父母态 | 规则、评判、纠正、命令 | “必须、应该、怎么又、早就说过”、绝对化、训诫 | “这个低级错误怎么还能出现？” | 发送者占据规范裁决位，常试图激活对方顺从儿童态 |
| 养育父母态 | 照顾、保护、安抚、代劳 | “别急、我来、注意休息、慢慢说” | “先别慌，我帮你一起看。” | 高位但支持；不应与控制态合并为“强势” |
| 成人态 | 基于当下事实、条件、选择和后果 | 数据、澄清问句、条件方案、明确责任 | “现在缺两项数据；A 今天交，B 明早补，可以吗？” | 最适合任务协商和冲突降级 |
| 顺应儿童态 | 讨好、畏缩、自责、依赖许可 | 反复道歉、“都听你的、不敢、我是不是又……” | “对不起，都是我的问题，你说怎么改我就怎么改。” | 自我降位，可能因惧责而过度承诺 |
| 自由/反抗态 | 自发玩乐，或抗拒控制 | “太爽了”、玩笑；或“凭什么、我偏不”、讽刺 | “凭什么每次都让我兜底？” | 需区分健康自发与反抗性对立 |

TA 对“位阶”的价值不在于判断谁职级高，而在于识别**谁在定义规则、谁在索取许可、谁在处理事实**。工作场景研究也显示，组织角色会影响请求方向、直接程度和缓和策略；上行请求通常更间接、更有缓和，下行指令往往拥有更高的行动权利，但礼貌和直接度仍受组织文化及关系亲疏影响。[^9][^10][^11]

每轮还可标注交易结构：

- **互补交易**：回应来自发起者预期的状态，交流容易继续。例如成人态问进度，成人态报数据。
- **交叉交易**：成人态问题被控制父母态斥责，或事实澄清被反抗儿童态理解为责备，交流容易中断。
- **隐蔽交易**：表层看似成人—成人，心理层却带讽刺、诱导、挑衅或讨好。TA 文献把它描述为同时包含显性社会消息与隐性心理消息。[^12][^13][^14]

**微信场景示例**：经理发“这么简单的数据都能弄错？”是“控制父母态 → 期待顺应儿童态”。智能辅助不宜建议“你别这么说话”，也不宜建议过度认错；更有效的成人态回复是：“第 3 行口径确实引用错了。我 17:00 前更正，同时补一项交叉核验，之后把结果发你。”这会把交易从责备—服从拉回事实—行动。

TA 的使用边界很重要：系统应输出“本轮呈现控制父母态，置信度中等”，而不是“对方是控制型人格”。TA 是实务型互动框架，不应替代临床评估，也不能仅凭一条文字断言心理状态。

### 高语境潜台词

Hall 的高/低语境区分认为，高语境交流把大量信息放在接收者已有知识、关系和情境中，显性消息可以很少；低语境交流则把更多信息编码在文字本身。 Grice 的会话含义理论进一步解释了接收者如何从“为何这样说、为何说得少、为何答非所问”推断说话者意义：人们通常假设对方在质量、数量、关联和方式上总体合作，并据偏离推导含义。[^15][^16][^17]

中国微信没有一个学界公认、互斥穷尽的“潜台词经典标签集”。较成熟的研究共识是：关系、面子、位阶、互惠与和谐会系统性影响直接程度；中国语境中的间接拒绝常借助解释、延期、替代方案、条件接受、感谢或省略来减少面子威胁。[^18][^19][^20][^21]

适合产品化的潜台词机制可整理为八类：

| 机制 | 定义 | 常见信号 | 微信例句 | 可能含义 |
|---|---|---|---|---|
| 共享省略 | 假设双方知道前情，不重复关键信息 | “还是老样子”“你知道的” | “老地方，还是那个时间。” | 调用共同知识，非信息不足 |
| 行动暗示 | 不直接下请求，通过陈述环境让对方补全行动 | 状态陈述、反问、提示困难 | “打印机好像又没纸了。” | 希望对方加纸或处理 |
| 委婉拒绝 | 用原因、延期、替代或模糊承诺代替“不” | “最近有点忙、改天、到时看” | “这周排得挺满，下次有机会一定。” | 大概率拒绝，但保留关系 |
| 面子维护 | 先肯定、感谢或自责，再提出异议 | “想法很好，不过……” | “方向我很认同，要不要再看看成本？” | 降低对对方能力或身份的威胁 |
| 位阶试探 | 通过模糊问句测试服从、权限或立场 | “你应该没问题吧？” | “这个你来处理，方便吧？” | 表面征询，实为弱指令 |
| 情绪侧显 | 不直说不满，通过简短、延迟、反常礼貌、撤回表达 | “嗯”“行吧”“随你” | 对长解释只回“收到。” | 可能不满、结束话题或仅确认，需看基线 |
| 承诺留白 | 避免形成可追责承诺 | 模态词、无主体、无时间、被动句 | “原则上可以推进。” | 有条件支持，不等于承诺执行 |
| 人情互惠 | 调用关系、旧帮助或群体身份增加顺从压力 | “自己人、上次我也……” | “都是自己人，这次先帮我顶一下。” | 请求资源，并激活互惠义务 |

面子研究区分“脸/廉”与“面子”：前者更偏群体对道德品格与可信度的认可，后者更偏社会声望、成就与位置；中国沟通中的面子具有明显的关系性、社会性和层级性。 因此，系统应识别“给台阶、保留回旋、避免公开否定”这些互动功能，而不是把所有间接表达标成虚伪或操控。[^22][^23][^24]

微信研究也观察到，高语境实践不仅在文字内容中出现，还可能通过延迟回复、点赞与否、图片无说明、群内含蓄规训等方式表达异议或关系变化。 但这些只能作为弱证据：延迟回复也可能来自忙碌、通知遗漏或习惯差异，必须与个人历史基线和同一对话中的变化结合。[^25]

## 六大研判维度

以下六维是面向“最新一条消息 + 最近多轮上下文”的推荐主架构。为满足机器学习和规则引擎需要，每维的主标签互斥且穷尽；当证据不足时必须选择“无法判断”。若一条消息包含多重诉求，应输出一个主标签和至多两个候选标签，不应破坏主标签互斥性。

### 互动位阶

**定义**：发送者在当前回合相对接收者采取的局部控制姿态，即谁在设定规则、分配任务、索取许可、挑战决定或协商选择。它不是组织职级，也不是稳定人格。

**判断依据**：指令权、许可语、称呼与敬语、直接度、责任归属、是否给出选择、是否允许拒绝、谁设定截止时间、是否挑战既有决定。Brown 与 Levinson 的礼貌框架将权力、社会距离和施加负担的大小视为影响面子威胁和礼貌策略的重要变量。[^26][^27]

| 枚举 | 操作定义 | 示例信号 |
|---|---|---|
| 自我降位 | 主动降低决定权，寻求许可或保护 | “您看是否可以”“都听你的” |
| 平等协商 | 双方选择权对称，可讨论条件 | “A、B 两种你倾向哪个？” |
| 轻度主导 | 推动对方行动，但仍留真实协商空间 | “建议今天先把框架定下来” |
| 强势支配 | 单方设规则、任务或截止，拒绝空间很小 | “今天下班前必须给我” |
| 挑战夺权 | 否定对方决定权、规则或资格 | “这事凭什么你说了算？” |
| 位阶不明 | 缺少角色或语言证据 | “看到了” |

### 核心需求

**定义**：对方最希望通过本轮互动获得的首要结果，强调“为什么发这条消息”，而不是表面句式。意图与情绪应分开：负面情绪可能对应求解释、求补救、求共情或求升级等完全不同的需求。[^28][^29]

**判断依据**：显性请求、未闭合任务、前文问题、情绪暴露、重复追问、资源交换、关系修复信号、是否要求决定或执行。

| 枚举 | 操作定义 | 典型例句 |
|---|---|---|
| 获取信息 | 需要事实、原因、状态或确认 | “现在进度到哪了？” |
| 推动行动 | 希望对方执行、停止或修改行为 | “麻烦把权限开一下。” |
| 辅助决策 | 希望获得判断、方案、背书或选择 | “两个报价你觉得选哪个？” |
| 情绪承接 | 希望被理解、安慰、认可或陪伴 | “最近真的有点撑不住。” |
| 关系维护 | 希望拉近、修复、确认或体面结束关系 | “昨天语气重了，不好意思。” |
| 获取资源 | 希望获得时间、钱、人脉、机会或让步 | “能不能借我一个人支持两天？” |
| 边界试探 | 测试可接受范围、服从度或底线 | “你应该不会介意吧？” |
| 需求不明 | 无法从上下文确定首要结果 | “呵呵。” |

### 回应期待

**定义**：对方期望接收者下一步完成的可观察回应。它是四耳模型中“诉求面”的产品化版本，并与 Searle 的指令、承诺、表达等 Speech Act 互补。Searle 的五大言语行为包括断言、指令、承诺、表达和宣告；它们描述一句话在社会互动中“做了什么”。[^30][^31]

**判断依据**：句式、被请求的行动者、问号、命令词、感谢/道歉、承诺交换、问题—回答或邀请—接受/拒绝等邻接对、前文尚未回应的动作。

| 枚举 | 操作定义 | 典型例句 |
|---|---|---|
| 仅需知晓 | 发送状态，不强求显性回复 | “我已到酒店，明早去现场。” |
| 确认收到 | 期待简短回执或理解确认 | “文件发你了，收到说一声。” |
| 提供信息 | 期待事实、解释或澄清 | “为什么预算多了 20%？” |
| 情绪回应 | 期待共情、认可或道歉 | “我当时真的挺难受的。” |
| 采取行动 | 期待执行、停止、修改或交付 | “请把旧链接撤掉。” |
| 作出选择 | 期待同意、拒绝、拍板或取舍 | “周三还是周四，你定一个。” |
| 给出承诺 | 期待明确负责人、时间或保证 | “你能确认明天一定上线吗？” |
| 期待不明 | 没有足够证据 | “行吧。” |

### 时间压力

**定义**：对方对回复或行动速度的要求，包括显式截止时间和由事件窗口、重复催促、风险后果产生的隐式时限。

**判断依据**：时间实体、“马上/尽快/有空”、倒计时、会议或发版节点、连续追问、逾期后果、消息频率、对方是否已经等待。ISO 24617-2 将时间管理单列为对话维度，说明“对话需要多少时间、何时继续”与任务内容本身是不同的信息类别。[^3][^32]

| 枚举 | 操作定义 | 处理建议 |
|---|---|---|
| 无需时限 | 明确不急或纯分享 | 正常节奏 |
| 常规跟进 | 有待办但没有迫近节点 | 当日或约定节奏 |
| 尽快处理 | 期望优先处理，但无硬截止 | 先回执并给预计时间 |
| 明确截止 | 给出具体日期、时刻或事件节点 | 重述截止并确认可行性 |
| 立即响应 | 正在发生、窗口极短或连续催促 | 先确认，再行动 |
| 时限冲突 | 多个期限矛盾或要求明显不可行 | 立即协商优先级 |
| 时限不明 | 上下文无法确定 | 主动澄清 |

### 边界风险

**定义**：本轮请求或互动对隐私、权益、合规、安全和自主选择造成的首要风险。该字段采用“最高优先风险”规则，因此主标签保持互斥；同时可另设非互斥 `risk_flags` 保存多个风险类型。

**判断依据**：是否要求敏感信息、金钱或账号操作，是否越过职责和同意，是否有欺骗、羞辱、威胁、胁迫、违法违规、自伤他伤或紧急安全信号；还要看请求者身份能否核验。

| 枚举 | 操作定义 | 典型信号 |
|---|---|---|
| 无显风险 | 常规信息或行动，没有明显越界 | 正常进度询问 |
| 轻微越界 | 不礼貌、过度打扰、职责模糊，但可协商 | 非工作时间反复催促 |
| 隐私敏感 | 涉及身份、健康、住址、聊天记录、账号凭证 | “把验证码发我” |
| 权益受损 | 涉及金钱、名誉、重大承诺、资源或不公平负担 | 垫资、背锅、无偿高负荷 |
| 合规高危 | 涉嫌欺骗、绕流程、违法违规或证据销毁 | “先走账，合同后补” |
| 强迫威胁 | 以惩罚、曝光、关系断裂等迫使服从 | “不答应我就发群里” |
| 人身危机 | 明确自伤、他伤、失联或现实安全危险 | “我不想活了” |
| 风险不明 | 身份、意图或上下文不足 | 陌生链接、模糊转账要求 |

风险规则应优先于“高情商回复”。例如收到“把验证码给我，领导急用”，系统首先应提示身份核验与拒绝共享，而不是生成更委婉的同意话术。

### 冲突状态

**定义**：当前互动从合作到关系破裂的烈度，依据语言行动和序列变化判断，而非只看正负情绪。CA 研究表明，拒绝、不同意等“非偏好回应”常出现延迟、缓和和理由；因此“说得客气”不等于没有分歧。[^6][^33][^4]

**判断依据**：否定和反驳、归责、讽刺、绝对化、重复争执、威胁、最后通牒、拉第三方、拒绝继续沟通、拉黑/退出等行动；同时比较对话前后温度和直接度变化。

| 枚举 | 操作定义 | 典型信号 |
|---|---|---|
| 合作一致 | 支持、接受、共同解决 | “可以，我来补。” |
| 轻微分歧 | 意见不同但仍围绕问题协商 | “我理解，不过建议换方案。” |
| 隐性不满 | 不满经冷淡、拖延、反常客气或暗示表达 | “好的，按您说的。”（结合前文） |
| 明确对立 | 直接否定、责备、争夺责任或决定权 | “这不是我的责任。” |
| 威胁升级 | 出现惩罚、曝光、投诉、最后通牒 | “今天不给就直接上报。” |
| 关系破裂 | 明确终止合作、拒绝对话、拉黑或退出 | “以后不用联系了。” |
| 冲突不明 | 信号不足或存在多种合理解释 | 单独一个“嗯” |

## Speech Act 与 CA 层

六维研判之下，还需要一个更“原子化”的对话行为层。Searle 五类适合理论总纲，但对产品过粗；ISO 24617-2 更适合多维标注，它将任务推进、发送者反馈、接收者反馈、轮次管理、时间管理、话语结构、自我修正、对方话语修正、社会义务等分开，并支持同一片段在不同维度承担多个功能；2020 版还支持书面、多模态及领域扩展。[^34][^35][^3]

面向微信可采用以下精简 Speech Act 集：

- 陈述：告知、报告、解释、评价、预测、归责。
- 询问：开放提问、是非提问、确认提问、反问、追问。
- 指令：请求、建议、提醒、命令、禁止、警告。
- 承诺：接受、拒绝、允诺、报价、让步、威胁。
- 表达：感谢、道歉、祝贺、抱怨、安慰、赞美。
- 反馈：收到、理解、同意、不同意、纠正、澄清。
- 结构：开场、转题、结束、催回、暂缓、恢复。

一个消息气泡可切成多个 functional segments。例如“方案不错，不过成本再核一下，明早给我”应切为“正向评价 + 转折异议 + 行动指令 + 截止时间”，不能只给一个“建议”标签。ISO 的核心思想正是让最小功能片段分别承载语义内容与交际功能。[^36][^37]

CA 还提供四个对微信非常重要的上下文特征：

- **邻接对**：问题—回答、请求—接受/拒绝、道歉—接受、邀请—接受/拒绝；第二部分缺失本身就是信号。
- **偏好组织**：接受和同意通常更直接；拒绝、不同意常带延迟、缓和和解释，这里的“偏好”是序列结构，不是个人喜欢。[^4][^6]
- **修复**：识别“不是这个意思”“你误会了”“准确说是……”等自我修正与他人修正。
- **序列位置**：同一句“行”作为首次答复、被催三次后的答复、争吵后的终止语，含义完全不同。

## 真实感微信案例

以下为基于常见单聊模式合成的匿名化示例，用于说明标注方法，不是私人聊天记录。

### 案例一：职场弱指令

**上下文**

- 对方：“客户明早十点要看版本。”
- 对方：“你今晚方便的话，再把首页过一遍？”

**研判**

- 四耳：事实为客户明早验收；自我揭示为对结果担忧；关系面为默认接收者承担质量责任但用“方便的话”缓和；诉求为今晚复核首页。
- Speech Act：背景告知 + 间接请求。
- TA：成人态为主，带轻度主导；不是单纯询问“是否方便”。
- 六维：`轻度主导 / 推动行动 / 采取行动 / 明确截止 / 无显风险 / 合作一致`。
- 建议回复：“可以。我今晚 22:00 前复核首页，发现问题直接标在文档里；其他页面明早再补一轮。”

### 案例二：委婉拒绝

**上下文**

- 你：“周六要不要一起吃饭？”
- 对方：“这周家里事情有点多，最近估计都比较忙，等缓过来再约哈。”

**研判**

- 表层 Speech Act 是解释和未来承诺，实际序列功能是“邀请—拒绝”。研究显示，拒绝作为非偏好回应常以解释、延期和模糊未来安排来缓和；中文拒绝研究也反复发现理由、延期和替代是高频策略。[^19][^38][^4]
- 六维：`平等协商 / 关系维护 / 仅需知晓 / 无需时限 / 无显风险 / 合作一致`。
- 不应判断为“讨厌你”；更稳妥的含义是“本次拒绝，关系仍保持，未来邀约承诺度低或未知”。
- 建议回复：“好，先忙家里的事，不急。等你方便再说。”

### 案例三：被动不满

**上下文**

- 你：“这次先不采用你的方案，按 A 方案推进。”
- 对方：“好的，都听您的。”

**研判**

- 单看文字可理解为服从；结合称呼突然从“你”变为“您”、绝对化“都听”、前文方案被否定，可能是反常礼貌和责任切割。
- TA 候选为顺应儿童态，也可能是隐蔽的反抗儿童态；两者必须并列候选，不能强判。
- 六维主标签可为：`自我降位 / 关系维护 / 确认收到 / 常规跟进 / 无显风险 / 隐性不满`，但冲突置信度只能给中等。
- 建议回复：“不是让你单纯服从。A 方案先跑一版，你担心的两个风险点也保留验证；如果数据不支持，我们再切回你的方案。”

### 案例四：边界与合规

**上下文**

- 对方：“先把客户名单导出来发我私人邮箱，系统权限明天再补，领导催得急。”

**研判**

- Speech Act：命令/请求 + 时间施压 + 权威借用。
- 四耳：事实是权限未开；自我面是急于绕过流程；关系面借“领导”提高服从压力；诉求是把客户数据转移到私人邮箱。
- 六维：`强势支配 / 获取资源 / 采取行动 / 立即响应 / 合规高危 / 轻微分歧`。
- 建议回复：“客户名单不能发私人邮箱。我可以现在走加急授权，或把脱敏汇总通过公司渠道发你；请把领导和数据负责人拉进来确认。”

### 案例五：情绪求助

**上下文**

- 对方：“我知道这事已经过去了，但一想到还是很难受，可能是我太矫情了。”

**研判**

- Speech Act：情绪披露 + 自我贬低；首要需求通常不是解决方案，而是被理解和接纳。
- 共情对话研究常把倾听者回应区分为提问、同意、确认、同情、鼓励、安慰、建议和祝愿；合适策略取决于对方情绪和阶段，而不是统一输出建议。[^39][^40][^41]
- 六维：`自我降位 / 情绪承接 / 情绪回应 / 无需时限 / 无显风险 / 合作一致`。
- 建议回复：“这不算矫情，说明那件事对你影响确实很大。你愿意说说最近是什么又勾起这种感觉的吗？”

## 业界与开源前沿

### 分类框架对照

| 体系 | 主要标签或指标 | 优点 | 对微信系统的借鉴 | 局限 |
|---|---|---|---|---|
| Searle Speech Acts | 断言、指令、承诺、表达、宣告 | 理论清晰，适合作顶层本体 | 识别一句话在“做什么” | 粒度太粗，不含序列、风险与关系 |
| ISO 24617-2 | 任务、反馈、轮次、时间、结构、修正、社会义务等多维功能 | 可多标签、可扩展、适用于书面和多模态对话[^3][^35] | 作为底层对话行为标准 | 完整实现成本高，需裁剪 |
| SWDA/DAMSL | 42 类，如陈述、问答、回声、同意、不同意、道歉 | 大规模通用对话行为基准；由更细标签聚合为 42 类[^42][^43] | 训练基础对话行为分类器 | 来自英语电话语料，文化与媒介有域差异 |
| DailyDialog | Inform、Question、Directive、Commissive；另有七类情绪 | 开放可用、多人研究复现方便[^44][^45][^46] | 多轮意图与情绪基线 | 标签过粗，且多数情绪为“无情绪” |
| 客服对话行为 | 12 类：陈述、感谢、是非问、确认、请求、开放问、回答、开闭场、表达等 | 贴近服务流程和自动路由[^47] | 适合工单、售后、客户成功 | 难覆盖亲密关系、位阶博弈和潜台词 |
| 共情意图 | 提问、同意、确认、鼓励、安慰、同情、祝愿、建议 | 将“怎么回应情绪”结构化[^39][^41] | 适合陪伴、冲突降级 | 不等于对方当前意图；需与风险门控结合 |
| Gong | 话语占比、最长独白、互动度、提问率、主题、异议、购买信号、风险和下一步 | 强行动导向，连接 CRM、辅导与成交[^48][^49][^50] | 增加“下一步是否明确、风险是否悬空、对方参与度” | 是商业产品能力，不是公开统一标签标准 |
| Chorus/ZoomInfo | 转录、话题、情绪变化、竞争者、异议、关键人、时间线、风险、行动建议 | 将会话信号与账户、联系人、CRM 串联[^51][^52][^53] | 将单条洞察放入关系史和任务状态 | 主要面向销售会议，不能直接迁移到私人微信 |

Gong 和 Chorus 的成熟之处，不是拥有一个神秘的“心理洞察标签表”，而是把洞察分成三层：**捕获层**（记录、转录、说话人）、**分析层**（主题、情绪、异议、参与度、风险）、**激活层**（CRM 字段、预警、辅导、下一步）。微信辅助系统也应如此设计：标签只有在能触发“澄清、确认、执行、升级、设边界、共情”等动作时才有价值。[^48][^51]

### 开源训练建议

可用数据不宜只选一个语料库：

- 使用 DailyDialog 训练基础 `inform/question/directive/commissive + emotion` 能力；其 Hugging Face 数据卡公开了对应字段与标签。[^45][^54]
- 使用 SWDA/DAMSL 学习更细的同意、回声、回答、反问、道歉等通用对话行为。[^42][^43]
- 使用 EmpatheticDialogues 衍生的共情意图分类学习“确认、安慰、鼓励、建议”等回应策略。[^40][^39]
- 使用客服域的 12 类对话行为学习开场、闭场、确认、请求和回答等流程行为。[^47]
- 最后必须构建中文微信风格的自有标注集，覆盖省略、表情符号、撤回、引用回复、语音转文字、反常敬语、关系基线和职场角色；英语语料只适合作预训练或标签原型。

## 系统落地方案

### 分层推理管线

为了兼顾毫秒级响应与解释性，推荐“轻模型主判 + 规则风险门 + 大模型离线蒸馏”的架构：

1. **上下文规范化**：保留发送者、时间间隔、引用关系、撤回、表情、语音转写置信度；把最近若干轮与长期关系摘要分开。
2. **功能片段切分**：按转折、并列、标点和动作边界切分，一条消息允许包含多个 Speech Act。
3. **显性抽取**：抽取人物、任务、时间、金额、否定、条件、承诺、风险关键词；这层尽量确定性。
4. **多头分类**：同时预测 Speech Act、四耳三类推断面、TA 姿态、六大研判维度、情绪与礼貌策略。
5. **序列校正**：依据邻接对、前文未完成任务、称呼变化、历史基线，修正末句孤立判断。
6. **风险门控**：隐私、转账、验证码、威胁、自伤他伤、违法违规优先于一般回复建议。
7. **策略生成**：先决定策略，再生成文字。策略可为确认、澄清、共情、给方案、设边界、谈条件、留证据、升级人工等。
8. **置信校准**：输出主标签、备选、证据、置信度和缺失信息；低置信度时生成澄清式建议，不生成断言式心理结论。

### 标注规范

高质量数据比扩大标签数更重要。标注员应按以下顺序工作：

- 先标文字可观察内容，再标语境推断，不允许把推断写进“事实”。
- 每个推断标签必须划出证据 span；只有依赖前文时，额外标注 `context_turn_ids`。
- 主标签必须遵循明确优先规则；多意图只保留候选，不让标注员任意多选。
- 对讽刺、反常礼貌、拖延拒绝、单字回复设置“双解释”机制。
- 用“表达出的情绪”代替“真实情绪”，用“当前姿态”代替“人格类型”。
- 分别计算各层一致率；不要用总准确率掩盖“事实很准、潜台词很差”。

情绪识别尤其依赖上下文、说话人状态、前序情绪和讽刺；脱离多轮历史的单句分类容易失真。 微信文本又缺少声调、表情和姿态等非语言线索，因此系统应把讽刺、冷淡、敌意等高推断标签设置更高阈值。[^55]

### 应对策略映射

| 研判组合 | 首选策略 | 避免做法 |
|---|---|---|
| 获取信息 + 提供信息 | 直接回答，未知项明确说明 | 先长篇共情却不回答问题 |
| 情绪承接 + 情绪回应 | 命名感受、确认影响、开放追问 | 立刻讲道理或给十条建议 |
| 推动行动 + 明确截止 | 确认范围、负责人、时间、完成标准 | 只回“好的”形成模糊承诺 |
| 自我降位 + 隐性不满 | 恢复选择权，邀请具体异议 | 顺势要求无条件服从 |
| 强势支配 + 明确对立 | 回到事实、边界和可执行选项 | 争夺语气高下、反击人格 |
| 合规高危/强迫威胁 | 拒绝、留痕、核验、必要时升级 | 为了礼貌而模糊底线 |
| 委婉拒绝 + 关系维护 | 接受本次拒绝，降低追问压力 | 把“改天”当确定承诺持续催促 |

## 关键设计原则

第一，**洞察必须是概率判断，不是心理宣判**。高语境并不意味着任何简短回复都有潜台词；系统应展示“最可能解释 + 合理备选 + 支持证据”。

第二，**把“内容、功能、关系、风险”分层**。同一句“可以”可能在内容上是接受，在关系上是顺从，在情绪上是不满，在风险上仍是高危操作；单一情感标签无法承担这些任务。

第三，**以对话序列为基本单位**。ISO 的多维思想和 CA 的邻接对、偏好组织、修复机制都表明，末句意义由前文行动约束；微信的引用、间隔、重复催促和称呼变化都是核心特征。[^3][^6][^4]

第四，**让建议回到成人—成人沟通**。无论对方采取控制父母态、顺应儿童态还是反抗姿态，助手优先建议事实、影响、需求、选择和下一步，而不是帮助用户升级操控或羞辱。

第五，**把安全与自主权放在“高情商”之前**。涉及隐私、金钱、合规、胁迫和人身危机时，系统应减少心理猜测，转向身份核验、明确拒绝、保存证据和人工/专业支持。

## 最终推荐

产品第一版不宜追求几十个“洞察维度”。建议采用：

- 底层：7 组精简 Speech Act + 功能片段切分。
- 解释层：四耳并行输出。
- 互动层：TA 当前姿态 + 互补/交叉/隐蔽交易。
- 决策层：六大核心维度及互斥主标签。
- 控制层：证据、置信度、备选解释、个人基线和安全门控。
- 行动层：确认、澄清、共情、协商、执行、设边界、升级七类回应策略。

这套结构既能承接经典人际沟通理论，又与 ISO 对话行为、CA 序列分析及 Gong/Chorus 的行动化思路兼容；最重要的是，它把“对方可能在表达什么”转化为可验证、可解释、可采取下一步行动的产品输出。
